Core Concepts & Theoretical Background

1. What is a TLB?

A Translation Lookaside Buffer (TLB) is a small, highly associative hardware cache embedded directly within the CPU's Memory Management Unit (MMU).

Because accessing page tables stored in main RAM is orders of magnitude slower than CPU registers, the TLB caches recently accessed Virtual Page Number (VPN) → Physical Frame Number (PFN) translations to dramatically accelerate address resolution.

Typical real-world TLBs hold between 64 and 1024 entries and operate within 0.5 to 1.5 clock cycles.

2. TLB Hit vs. TLB Miss

TLB Hit: The CPU looks up the requested VPN in the TLB associative tags. If a valid match exists, the Physical Frame Number (PFN) is returned instantaneously. Memory access penalty is strictly tTLB + tMEM.

TLB Miss: The requested VPN is absent from the TLB. The hardware MMU (or OS software walk) must consult the page table located in main memory, requiring an extra memory access before populating the TLB entry.

Miss latency: tTLB + 2 × tMEM (1 access for page table + 1 access for requested data).

3. TLB Miss vs. Page Fault (Viva Gold)

Students often confuse these two events, but they occur at completely different architectural layers:

Characteristic TLB Miss Page Fault
Nature Hardware / MMU cache miss OS Interrupt / Software Trap
RAM Presence Page IS in RAM; translation absent from cache Page is NOT in RAM (on disk or unallocated)
Resolution Cost Nanoseconds (~100ns RAM read) Milliseconds (~5-10ms Disk I/O)
This lab assumes all virtual pages are mapped and resident in RAM, simulating TLB hits and misses without page faults.

4. Effective Access Time (EAT)

Effective Access Time models the weighted average latency experienced by the processor during memory references:

EAT = h × (t + m) + (1 − h) × (t + 2m)

Where:
• h = TLB hit ratio (0.0 to 1.0)
• t = TLB lookup latency (e.g. 10 ns)
• m = Main memory access latency (e.g. 100 ns)

Even a modest 80% hit ratio slashes average memory access time from 210 ns down to 130 ns, delivering a 38% speedup.

5. FIFO vs. LRU Replacement

When the TLB capacity is exhausted, an existing entry must be evicted:

• FIFO (First-In, First-Out): Evicts the entry that has resided in the TLB the longest. Crucially, hits do not alter insertion order, making FIFO vulnerable to evicting heavily accessed pages (Belady's anomaly).

• LRU (Least Recently Used): Evicts the entry unused for the longest interval. Every hit refreshes the entry's recency timestamp, protecting hot pages.

6. Locality of Reference

TLB effectiveness relies heavily on the principle of locality:

• Temporal Locality: If a memory location is accessed, nearby instructions or data are likely to be accessed again soon (demonstrated by Preset 1).

• Spatial Locality: Accessing address A makes accessing address A + 4 highly probable. Because an entire page shares the same VPN, sequential instructions generate consecutive TLB hits (demonstrated by Preset 2).

Q1: What exact hardware steps take place during a TLB hit? +
  1. The CPU generates a virtual memory address VA and partitions it into a Virtual Page Number (VPN) and Page Offset (d).
  2. The MMU conducts an associative search across the TLB tag array using the VPN.
  3. A valid matching entry is found (TLB Hit), returning the Physical Frame Number (PFN) in tTLB time.
  4. The Physical Address is formed by concatenating PFN with Offset: PA = (PFN × PageSize) + Offset.
  5. A single main memory access is dispatched to read or write the operand at PA. No page table walk is required!
Q2: Why is a TLB miss not necessarily a page fault? +

A TLB miss simply means the translation tag was not found in the fast cache. The actual page may very well be resident in physical RAM. The MMU simply accesses the resident Page Table in memory, retrieves the valid PFN, and inserts it into the TLB (taking ~100 nanoseconds).

A page fault only occurs if the page table entry itself has its Valid/Present bit cleared to 0, signaling that the page resides on secondary storage (swap/disk) and requires an OS interrupt, disk I/O, and page replacement (taking ~10 milliseconds).

Q3: How does increasing TLB hit ratio impact Effective Access Time mathematically? +

Recall the single-level EAT equation: EAT = t + m + (1 − h) × m.

Every miss inflicts an entire extra memory latency cycle (m). If t = 10 ns and m = 100 ns:

  • With 0% Hit Ratio (h = 0): EAT = 10 + 200 = 210 ns.
  • With 50% Hit Ratio (h = 0.5): EAT = 10 + 100 + 50 = 160 ns.
  • With 95% Hit Ratio (h = 0.95): EAT = 10 + 100 + 5 = 115 ns (near-native RAM speed).
